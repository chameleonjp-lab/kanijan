## 実装結果とルール

ホームに任意名・公開説明・言語・音設定をまとめ、不要になった必須名専用画面を除去した。名前は10コードポイントまで、既存 `kanijan_display_name` を維持。変更/空欄は入力時に保存し、プレイ開始時の名前を固定する。IME変換確定からの開始処理はない。

採点、60秒、PERFECT/OK判定窓、衝突、50段の🍥出現、10/20/30段の加点、0点の送信除外（明示リタイアは従来通り送信）を維持。問題は絵文字の接近タイミング判断であり、日本語語彙依存の問題はない。翻訳は表示だけに適用し、内部終了理由・判定値を保持する。

15言語×84表示文を `i18n/*.json` に定義。ホーム、説明、ゲームHUD、判定効果、結果、ランキング、通信失敗/再試行、音、共有を翻訳。保存言語→対応ブラウザ言語→英語の順。言語変更は表示更新だけで、時間/問題/確定結果/送信を変更しない。`tools/build-locales.py` がカタログを公開HTMLに埋め込み、CIは生成物の一致を検証する。

既存集計 `get_best_score_ranking(p_limit=30)` を利用し、`rank_no` の同順位を表示。上位30プレイの名前除去ではない。画面から参加総数や圏外順位は推測しない。読み込み/空/失敗/再試行を翻訳し、古い取得と古いプレイからの応答を無視する。名前は文字としてescapeし、プレイヤー名は翻訳しない。既存DBは名前をキーにするため、同名別人の分離と改名後の本人継続は未解決。

Xボタンは両画面黒白、44px以上、折返し対応。ホームは特徴と現在の正式URL、結果は今回の確定点数/高さ/コンボとURL。名前・推定順位・参加人数は含めない。X投稿確認画面を開き、開けなければコピー画面を表示。投稿完了とは言わない。

## 記録・通信・関連PR

既存 `game_scores` / `score_runs` / `players`、slug `kanijan`、降順整数スコア、保存名キーを削除・変更しない。新規保存は `kanijan:language`, `kanijan:sound`, `kanijan:volume`, `kanijan:last-result:v1` とプレイごとの `kanijan:pending-result:v1:<UUID>` に分離する。参加者IDを勝手に発行し直さない。

登録は実験場 [PR #43](https://github.com/chameleonjp-lab/chameleonjp_lab/pull/43) の `public.submit_score_once_shared_v1` に依存する。開始時UUIDと名前、確定時スコア/結果/クライアント版を固定し、通信前に端末へ保存する。送信済み/待ち/失敗を区別し、失敗・再読込後は同じUUID/同じpayloadで再試行する。送信済みや名前なしの過去結果は再送しない。失敗した過去プレイはUUIDごとの台帳に残し、次のプレイで上書きしない。ホームの再試行からそれぞれの開始名/確定結果のまま送る。応答の名前・整数スコア・登録回数・duplicateフラグを確認し、不完全な応答を成功扱いしない。RPC未適用時に旧APIへfallbackしない。8秒で通信を中断し、結果とランキング閲覧を保つ。登録成功後はランキングを再取得し、先に開始した古い応答を採用しない。

端末保存がブラウザ設定/容量で使えない場合もゲームとその画面の結果は利用可能だが、再読込後の復元は保証できない。新しいUUIDを作って失敗結果を再送する処理はない。Codeberg/GitHubは別originのため端末設定/名前/今回結果は自動移行しない。旧データを残し、移行時にゲーム限定export/importまたは本人の手動再設定が必要。サーバーの名前キー問題とは分けて扱う。

## 効果音一覧

従来は無音スタブだった。ブラウザ生成音のみを使う。初回オン/音量0.5、保存off/0を有効設定として維持。AudioContextは操作時のみ初期化し、失敗しても開始できる。suspended時はresumeを試してそのイベントを破棄し、復帰後に古い音を予約再生しない。hidden時は音源を停止、ミュート/0でも停止する。全音源は終了時disconnectし最大6声、通常音は80ms抑制。

|イベント|役割・条件|重複抑制・実装|
|---|---|---|
|開始|開始ボタンで準備開始を示す2音|startReady / GameSound.play(start)、80ms|
|PERFECT/OK|画面と同じ成功判定を示す2音|applySuccess、節目があれば節目音のみ|
|早すぎ/衝突|画面と同じ失敗を示す低い2音|applyFailure、解決済みplatformは再生しない|
|10/20/30段|既存ボーナスの節目3音|applySuccess、以前の音を停止|
|終了/リタイア|確定終了を示す下降3音|finishGame、PLAYINGから1回、以前の音を停止|

音だけで正解が分かる事前予告は追加しない。実際の聴取、iPhone実機、長時間負荷は未確認。

2. **マージ前** Settings → Pages → Build and deployment → Source = **GitHub Actions**。`github-pages` environmentの既存保護を維持し `main` を許可。legacy公開のままなら検証を迂回するので先に変更する。ここでは設定を変更していない。
3. ユーザーがこのPRをマージ。PR時はvalidateのみ、main push時にそのコミットを検証/成果物化/公開。失敗時はdeployしない。concurrency取消・deploy前HEAD確認・Pages source確認で古い実行/二重公開を防ぐ。
4. APIが示す実URLで新コミットのホーム→プレイ→正常終了/失敗→結果、ランキング、共有、保存設定を確認する。
5. 新URLの機能確認後に正式URL/メタ情報PR、実験場 `games.game_url` / `share_text` 更新、旧ページ案内の順に切り替える。DB旧値を保存しslug+旧URL条件付きUPDATE、SELECTで読み戻す。このPRでは未適用。

公開対象は単一 `index.html` と `.nojekyll`。翻訳/音/実装はHTMLに含まれ、開発資料/テスト/秘密情報は公開しない。追加ローカルassetはmanifest検証で拒否し、明示拡張を必須とする。service workerは追加せず、保存情報の一括削除を行わない。
