# 音設定の読取失敗時の保全

## 対象と変更

GitHub main `0134ecc251b738079cb478eb5c6989bd59fd4b3f` を基準とするローカル候補です。2026-11-05に取得した GitHub 公開版 https://chameleonjp-lab.github.io/kanijan/ は、このコミットの index.html と一致しました。実験場に登録された https://chameleonjp.codeberg.page/kanijan/ は別の旧版です。この候補は登録先の旧版には反映されず、公開先や登録情報も変更しません。

起動時に localStorage の読取が例外になると、既存の「オフ」や音量「0」を未設定と同じように扱い、オン・0.5で起動していました。さらに別の音設定を操作すると、両キーを保存して読めなかった設定まで上書きしていました。

読取例外の場合のみ、その画面内ではオフ・音量0として扱います。キーが本当に存在しない場合の初期値はオン・0.5のままです。保存は利用者が明示的に変更したキーだけに限定し、他方の既存値を維持します。読取失敗した値の再読込・移行・削除は行いません。利用者が同じ設定を明示的に操作した場合は、その新しい値で保存を試みます。

## 記録と識別情報を分けた制約

- サーバー記録: この変更はランキング、スコア送信、DB、RPCに触れません。既存サーバー記録の移行や継承を検証したものではありません。
- 端末内保存: 対象は `kanijan:sound` と `kanijan:volume` のみです。結果スナップショット、送信待ち、履歴、言語は変更しません。プレイ途中からの復帰や自己ベストの追加も行いません。保存APIの例外や黙った書込失敗は従来どおり画面内の変更だけとなる場合があり、永続化成功を保証する表示・読戻し確認は追加していません。
- 参加者識別: 保存名 `kanijan_display_name`、送信ID、名前の照合規則は変更しません。サーバー上の同一参加者への紐付けが維持されるとの保証はしていません。
- 配信元の相違: CodebergとGitHubは別オリジンで、localStorageは自動で共有されません。公開先を切り替える場合は旧版と旧保存値を残し、別途、旧版の実際の保存項目を調べた上で、利用者が確認できる書出し・取込み手順を設計する必要があります。本候補は移行処理を実装しません。

## 確認

実際のHTMLから音処理を取り出し、外部通信なしのNode VMで読取例外を再現しました。修正前は追加5件中3件失敗、修正後は成功しました。既存の `tools/audio.test.mjs` に回帰を追加したため、現在のCIの音テスト対象に含まれます。通常の設定保存・再読込も確認し、保存処理を何もしない実装に変えた変異は検出されました。

ローカルの `node --test tools/*.test.mjs` は54件成功、`python3 tools/check-site.py` と `python3 tools/build-locales.py --check` は成功しました。実ブラウザ、公開環境での操作、候補のCI、Vitest、実ストレージ障害、音の聴取は未実施です。ブラウザ・ストレージ・音声ノードの境界はテスト用代替であり、これらの検査を実機試験と同一視できません。
